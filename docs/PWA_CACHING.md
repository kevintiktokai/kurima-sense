# PWA Caching Strategy

The KurimaSense service worker is generated by `@ducanh2912/next-pwa` and
augmented by our custom worker at [`worker/index.ts`](../worker/index.ts).
Each route below is a separate Workbox cache with its own TTL, eviction
rules, and failure behavior. Read this file before changing the SW — a
miscaching bug is the #1 cause of "why is the app showing stale data".

| # | Trigger | Strategy | Cache name | TTL | Max entries | On failure |
|---|---|---|---|---|---|---|
| 1 | Precache: `_next/*` static build output | precache | `workbox-precache-v2-*` | until build hash changes | n/a | network |
| 2 | Precache: `/offline` (force-added) | precache | `workbox-precache-v2-*` | until build hash changes | 1 | served by recipe #8 |
| 3 | Same-origin `GET /api/*` | NetworkFirst (5s timeout) | `api-cache` | 1 day | 100 | falls back to cached response; if miss → network error bubbles to caller |
| 4 | Same-origin `POST/PUT/DELETE /api/*` | NetworkOnly + BackgroundSync | (no cache; queue `mutation-queue`) | retry window 24h | n/a | queues request and replays when `online` event fires |
| 5a | Map raster tiles (`*.arcgisonline.com`, `*.tile.openstreetmap.org`) | none (network only) | (not cached) | n/a | n/a | network — never served stale |
| 5b | `request.destination === 'image'` (excluding map tiles) | CacheFirst | `images-v2` | 30 days | 200 | network error if not yet cached |
| 6 | `fonts.googleapis.com` | StaleWhileRevalidate | `google-fonts-stylesheets` | (no expiration) | unlimited | network error if not yet cached |
| 7 | `fonts.gstatic.com` | CacheFirst | `google-fonts-webfonts` | 1 year | 30 | network error if not yet cached |
| 8 | `request.mode === 'navigate'` | NetworkFirst (3s timeout) | `pages` | (no expiration; NetworkFirst keeps last response) | unlimited | falls to recipe #9 |
| 9 | Any unhandled failure during navigation | offlineFallback recipe → precached `/offline` | `workbox-precache-v2-*` | n/a | n/a | propagates if `/offline` was never installed |

## Why these choices

### `api-cache` (GET) — NetworkFirst, 1 day
Farmers need fresh yields and field state when they're connected, but a
day-old projection is better than nothing during a power cut or a trip
into a no-signal valley. 5-second network timeout keeps the UI snappy on
flaky cellular. 100-entry cap is enough for the working set of one farm
without ballooning storage on entry-level Android devices.

### Mutation queue — NetworkOnly + BackgroundSync, 24h retention
A POST to `/api/activities` while offline is queued in IndexedDB under
the `mutation-queue` name. When the browser fires the `online` event (or
the next time the SW runs after coming back online), Workbox replays the
queue in order. The 24-hour retention covers a long weekend without
connectivity; anything older than that gets dropped to prevent stale
mutations clobbering newer state on the server.

> **The order of replay is the order of original submission.** If the API
> requires idempotency keys, the client must include them on the original
> request — the SW does not add them automatically.

### Map raster tiles — NOT cached
Map tiles (`*.arcgisonline.com` World Imagery, `*.tile.openstreetmap.org`)
are fetched as `image` requests, so they would otherwise fall into the
CacheFirst image route. They must not: caching an opaque/error tile response
(the old route accepted statuses `[0, 200]`) and CacheFirst-serving it for 30
days is what blanked the production portfolio map. The image matcher now
excludes these hosts (`MAP_TILE_HOST`), so tiles always go to the network and
are never served stale. The poisoned legacy `images` cache is deleted on SW
activation, and the renamed `images-v2` cache only accepts status `200`.

### `images-v2` — CacheFirst, 30 days, status 200 only
Field photos and UI assets are large and largely immutable: a
yesterday's-photo is still yesterday's photo. 30 days × 200 entries is a
reasonable cap (~100–200 MB depending on photo size) and the LRU eviction
in `ExpirationPlugin` quietly evicts oldest entries first. Only real `200`
responses are cached — never opaque (`0`) or error responses.

### Google Fonts — split into two caches
Material Symbols (and any other Google-hosted font) needs both the CSS
stylesheet and the woff2 files. The stylesheet uses
StaleWhileRevalidate so we pick up Google's font subset updates, while
the actual font files are immutable and pinned for a year.

### `pages` — NetworkFirst, 3s timeout
Most app surfaces are navigation requests. 3 seconds is the sweet spot
where dropped/flaky cellular gets fallback-rendered fast but a healthy
connection wins consistently. We don't cap entries because pages are
small HTML responses and the SW's overall storage quota is the real
ceiling.

### Offline fallback
`offlineFallback({ pageFallback: '/offline' })` registers a single catch
handler. It only fires when nothing else can satisfy the request — for
instance, a navigation to a route that was never cached, while offline.
The `/offline` page is force-added to the precache manifest via
`additionalManifestEntries` in `next.config.ts`, so it's always available
after the first successful SW install.

## Cache invalidation

- **Precache**: Workbox compares the precache manifest hash on each
  install. When `next build` produces different hashes, the new SW
  installs, the old precache is purged at activation
  (`cleanupOutdatedCaches: true`).
- **Runtime caches**: `ExpirationPlugin` evicts on read/write — entries
  older than `maxAgeSeconds` or beyond `maxEntries` are dropped.
- **Mutation queue**: entries older than `maxRetentionTime` (24h) are
  dropped at replay time.
- **All caches**: bump `SW_VERSION` in `worker/index.ts` for a
  human-readable marker in the activation log. To actually invalidate
  runtime caches across all clients, change the cache name (e.g.
  `api-cache` → `api-cache-v2`).

## Debugging

1. **Confirm the SW is running**: Chrome DevTools → Application → Service
   Workers. The activation log line `[SW] KurimaSense service worker
   activated, version X.Y.Z` should appear in the Console.
2. **Inspect a cache**: Application → Cache Storage → pick the cache
   name from the table above.
3. **Test offline**: Network tab → toggle "Offline". Cached pages should
   load; uncached navigations should land on `/offline`.
4. **Test the mutation queue**:
   - Go offline.
   - Trigger an API mutation (e.g. log an activity).
   - In DevTools → Application → IndexedDB → `workbox-background-sync` →
     `requests` — the request should be present.
   - Toggle online. Within a few seconds the request should replay and
     the IndexedDB entry should disappear.
5. **Force a fresh SW**: DevTools → Application → Service Workers →
   "Unregister", then hard reload. Useful when a runtime cache is hiding
   a bug.

## When to add a new route

Before adding a `registerRoute` call, ask:

1. Is this request safely cacheable? (Auth-bearing API calls usually
   need NetworkFirst-with-fallback or NetworkOnly, not CacheFirst.)
2. Is there a privacy concern? (User-specific responses should not land
   in a cache that survives logout — use NetworkOnly or clear the cache
   on sign-out.)
3. What's the user impact if the cached copy is stale by a day? An
   hour? If the answer is "very bad", NetworkFirst with a short
   `networkTimeoutSeconds`. If "no impact", CacheFirst.

Add the new route to the table at the top of this file before merging.
